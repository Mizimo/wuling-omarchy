# Phase B — themes and foundations

Implementation against inbox v406 and design `c6e52a4`. Verification uses stock
Omarchy 4.0.6-1 and 4.5.0rc2-1 in disposable VMs. Raw captures, inventories and
logs are kept outside git in the `wb1` round; only the requested product
preview images ship in `theme/`.

## Delivered structure

`tokens/wuling.json` generates four themes and shared style data. The mappings
were compared semantically with the approved draft before replacing it.
Generation copies the approved backgrounds and boot marks, validates both menu
selection modes, compares generated bytes, and checks image hashes. Each theme
has all three backgrounds with its own name in every filename. The old design
theme generator is removed; design rendering and prototype tools remain.

The bundled fonts are Geist, Geist Mono, Barlow Condensed and the mapped subset
of Material Symbols Sharp, with licences and hashes. CJK remains Omarchy's.
The repository guides document ownership and verification; the installed
`wuling` skill documents safe user customisation.

The Python standard-library command family provides typed settings, effective
values with their origins, a phase-B status stub, metadata and diagnostics.
Other Omarchy themes provide their palette while retaining field geometry.
`menu.selected` regenerates complete owned theme directories and uses the
installed `omarchy theme refresh` wrapper. This preserves the chosen background
and uses 4.5's native wait for app retints.

The user-level installer prints a plan, asks for consent unless given `--yes`,
refuses conflicts and edited owned resources, and records a recoverable
transaction. Repeated updates preserve overrides. Removal restores the prior
theme and unchanged official theme effects, preserves user edits, and removes
unchanged owned resources. Fastfetch is optional and owns only its JSONC logo
member. Skill links are added only to existing agent directories. No privileged
operation, default binding or authentication replacement is part of install.
Boot unlock is a separate official Omarchy operation.

  missing final newlines, repeat installation/removal, existing-name conflicts,
  edited resources, override preservation, interrupted transactions, late
  failures and consecutive menu settings followed by an update.
- Both VMs: repeated install/remove produced a zero-difference `.config`
  inventory. The run includes optional fastfetch. A late injected font-cache
  failure also rolled back to the exact inventory. Conflicts and edited themes
  were refused; removal retained the fixture's edits and overrides.
- Both VMs: MIST and PAPER `edge` → `fill`, a repeat install, and an official
  same-theme application retained the selected mode. Settings updates and
  repeat installation retained the third background. Real menu captures show

- Four themes × three images × four real output sizes × two versions:
  96 stable captures at 1920×1080, 1920×1200, 1920×1280 and 2520×1080. The
  approved content remains visible. A numerical comparison against the source
  images' cover crop, excluding the bar/cursor, had worst mean RGB error 2.62
  on the 0–255 scale. This check accompanies visual inspection; it is not a
  synthetic screenshot. Filename changes in v405 do not alter these pixels.
- 4.0.6: all 12 directed transitions between WULING themes selected the new
  preset's first background. All four three-image cycles passed.
- 4.5: from the clean checkpoint, all four first visits selected their preset
  defaults and all four cycles passed. After choosing each third background,
  all 12 directed return paths restored that selection. This retains native
  per-theme memory, as ruled in v406; no hook or background-state edit is used.
- The real Plymouth daemon and password request displayed both approved marks

- `wuling.toml` survives the native git-theme filter on both versions. The

## Findings and documentation follow-up

Omarchy's lightweight theme parser requires bare TOML keys; valid quoted TOML
keys were ignored in the first candidate. The generator now emits native keys,
and all visual acceptance uses that corrected version. Native dconf values may
also differ from a theme's defaults. Removal preserves custom values and restores
identical logical databases byte for byte only when no unrelated values changed.

A consecutive-settings test caught transaction backup files entering a theme's
ownership hash. Settings now replace whole staged theme directories, keeping
backups outside both the theme resource and Omarchy's staging input.

A shared-host I/O/memory-pressure episode delayed VM rendering and HAPI. A guest
wait stack was in KVM asynchronous page-fault handling. Captures made while
rendering was stalled or transitioning were rejected; the completed background
matrix uses stable captures after recovery. This is not attributed to product
QML: phase B loads no custom QML into the shell.

DESIGN §3 should point its exact colour/shell mappings to `tokens/wuling.json`
and `bin/lib/wuling/theme.py` instead of the removed `design/theme-draft.py`.
The BRIEF's historical source reference can remain as provenance.

README can link the installation and command contract in `bin/README.md`.
